# 从图片/图纸还原建筑 —— AI 还原作业指南

> 目标:仅凭参考照片、图纸 PDF 或文字资料,让 AI 产出可用的 SketchUp 模型。
> 已验证案例:流水别墅(常识推定级)、拉塔皮住宅 Maison Latapie(图纸实测级,12×12.6m 单坡)。

## 还原精度分级(先声明,再动手)

| 级别 | 内容 | 需要的资料 |
|---|---|---|
| L1 体块级 | 层数、体量、朝向、大比例 | 1-2 张照片或文字描述 |
| L2 深化级 | 真实尺寸、开口位置、材质分区、特征构件 | 图纸(平/立/剖面)或带比例尺的图片 |
| L3 施工级 | 节点、厚度、构造分层 | 施工图 |

**动手前必须声明本次目标级别和资料缺口**,不假装精确。

## 资料获取与转换

| 资料 | 处理办法 |
|---|---|
| PDF 图纸 | `render_pdf.ps1`(WinRT 系统API,无需安装)逐页转 PNG → AI 读图 |
| 网页截图/照片 | 直接喂给 AI 读图 |
| DWG | 走 `pipeline/` 的 DWG→DXF→JSON 管线 |
| 网页资料 | WebFetch 抓项目页(尺寸、年代、材料) |

**尺寸标定**:用图上比例尺做像素比换算(比例尺两端像素距 ÷ 标注长度 = px/m);无比例尺时用门窗(门 2.1m、窗台 0.9m)或层高(住宅 2.8-3m)推定,**并标记"推定"**。

## 建模骨架(参考 examples/)

```ruby
# 1. 常量: SKP 路径、单位助手 m(v)=v*39.3701
# 2. 清场: entities.clear! + definitions.remove(未用) + layers/materials purge
# 3. 材质: MAT_部位_名称 命名
# 4. 分组即用即建: 每个部位 group(name, tag) 后立刻填几何(空组会被清理)
# 5. 基元: box(六面着色, 材质先于 pushpull)/plate(任意四边形面, 用于楔形与斜板)/cyl/tree
# 6. 场景与出图: PAGES_ADD 探测(:add)+ 直控相机出图(不依赖页面相机)
```

## 视觉闭环(每轮必做)

```
建 → 桥出 4 视角 → AI 读图与参考对照:
  体量对不对?比例对不对?有没有浮空/穿模/漏项?
→ 修脚本 → 再出图 → 循环 2-3 轮 → su_save
```

**已知硬限制**:SketchUp 失焦/最小化时视图命令失效(见 09 篇);出图前把 SketchUp 调到前台。

## 坐标化易错点(全部踩过)

1. pushpull 后原面引用失效 → 材质先设、边线先捕获。
2. 空组会被清理 → 分组即用即建。
3. 方法定义里用不了脚本的局部变量 → 方法内用 `Sketchup.active_model`。
4. 相机取景按"建筑尺寸"算距离,别按"场地对角线"(会把房子拍成蚂蚁)。
5. 单位助手全程一致(m 或 ft 二选一),临时变量别传原始英寸。
6. Windows 命令行传中文 JSON 会坏 → 请求体走 UTF-8 文件。
